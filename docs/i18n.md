# Interface language (i18n)

Clovy's interface is available in **English** and **Português (Brasil)**. The
choice lives in Settings > Appearance > Interface language (and on the first
onboarding step) and is independent of the dictation/transcription language.
Design rationale: [ADR-0056](adr/0056-interface-language-uses-an-in-repo-typed-catalog.md).

## Using it in code

```ts
import { t, useT, useTRich, formatDate, formatNumber } from "../i18n";

function Example({ count, name }: { count: number; name: string }) {
  const t = useT(); // every component that renders copy calls the hook
  return <p aria-label={t("notes.list.aria")}>{t("notes.count", { count })}</p>;
}
```

- Catalogs: `src/i18n/messages/<namespace>.ts`, one per product area. Keys are
  prefixed by the namespace (`settings.theme.title`). English is the source of
  truth; the `pt-BR` block must contain the same keys (TypeScript enforces it).
- Plurals: `{ one: "{count} note", other: "{count} notes" }`, selected with
  `Intl.PluralRules`; an optional `zero` form overrides 0. Portuguese 0 uses
  `other` ("0 notas").
- Interpolation: `{name}`; numeric params are formatted for the locale. Pass a
  string for ids or years that must stay raw.
- Markup inside a sentence: `useTRich()` with `<link>…</link>` in the catalog and
  a `link: (chunks) => <a>…</a>` param. Never concatenate translated fragments.
- Non-React code calls `t()` at use time, never at module load. Exported option
  tables keep their shape with getters (`get label() { return t(...) }`).
- Dates and numbers: `formatDate`, `formatNumber`, `formatRelativeTime`,
  `formatList`, or pass `intlLocale()` to `Intl`. English returns `undefined`
  (system regional format, unchanged); Portuguese uses `pt-BR`.

## What is not translated

User content (note titles and bodies, transcripts, session titles, folder
names), model output, text sent to the model as instructions or prompts,
storage keys, event names and wire identifiers, model and provider names,
brand names (Clovy, OpenSoftware, OS Accounts, MCP), keyboard glyphs, and
dev-only surfaces (`*-demo.ts`, `src/styleguide/`, `playground/`,
`*-preview.html`). Replies to paired companion devices and agent-facing tool
errors stay English because they are protocol text, not app screens.

Known limits: AppKit-inserted menu items (window list, "Start Dictation",
"Emoji & Symbols") and macOS permission prompts (`NSMicrophoneUsageDescription`
and friends) follow the bundle's localizations, which remain English-only;
localizing them needs `pt-BR.lproj/InfoPlist.strings` in the macOS bundle and a
macOS validation pass. Error text produced by Rust or Clovy API is shown as
received. Values persisted at creation time keep the language active then.

## Adding a language

1. Add the tag to `SUPPORTED_LOCALES` and `INTERFACE_LOCALE_OPTIONS` (native
   name) in `src/i18n/locale.ts`, and teach `normalizeLocale` to map it.
2. Add the new block to every `src/i18n/messages/*.ts`; `pnpm typecheck` lists
   each missing key.
3. Extend `UiLocale` in `src-tauri/src/interface_locale.rs` and the extension's
   `extension/src/i18n.ts` plus `extension/public/_locales/`.
4. `src/test/i18n-core.test.tsx` checks placeholders, plural shapes, dashes, and
   namespace prefixes for every catalog.
